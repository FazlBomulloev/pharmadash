## 1. Фактические поля

Проверено на живых карточках парацетамола. Наличие поля в выгрузке зависит
от того, какой ETL мы напишем — здесь то, что **фактически показано на
карточке товара** и можно спарсить.

### 1.1 eApteka (пример: «Парацетамол Реневал таблетки шипучие 500 мг 10 шт»)

| Поле | Пример | Тип |
|---|---|---|
| Название | «Парацетамол Реневал таблетки шипучие 500 мг 10 шт» | str |
| Бренд/ТМ (отдельно) | «Реневал» | str |
| МНН | «Парацетамол» | str |
| Производитель + страна | «Обновление ПФК АО, Россия» | str+str |
| Форма | «таблетки шипучие» (в названии) | str |
| Дозировка | «500 мг» | str |
| Размер упаковки | «10 шт» | str |
| Розничная цена | 189 ₽ | float |
| Скидка (%) и старая цена | «−19%», старая 5 159 → 4 159 ₽ | float |
| Rx/OTC | «Самовывоз: рецептурный» | bool |
| Рейтинг | ★★★★★, 2 отзыва | float, int |
| Мин. цена аналога | «Аналоги от 38 ₽» | float |
| Доставка | «В аптеку сегодня или позже» | str |
| «Все формы выпуска» | dropdown с вариантами того же МНН+ТМ | list |

### 1.2 Ригла (пример: «Парацетамол таблетки 500 мг №20»)

| Поле | Пример | Тип |
|---|---|---|
| Название | «Парацетамол таблетки 500 мг №20» | str |
| Производитель | «Фармстандарт-Лексредства…» | str |
| Форма/доза/№ | «таблетки», «500 мг», «№20» (в названии) | str |
| Розничная цена | 38 ₽ | float |
| Скидка (%) | скидка в бейдже, старую цену видно не всегда | float |
| Наличие | «В наличии» / без флага | bool |
| Мин. цена аналога | «от 85 ₽» | float |
| Рассрочка (Яндекс Сплит) | «4 × 10 ₽» — 4 платежа | bool + float |

Ригла даёт **~340** SKU по парацетамолу — самая широкая ассортиментная
матрица из трёх. Есть фильтр «Международное непатентованное название на
кириллице» — сеть сама держит справочник МНН и умеет фильтровать по нему.

### 1.3 Озерки (пример: «Парацетамол Эвалар 500 мг таблетки шипучие 12 шт»)

| Поле | Пример | Тип |
|---|---|---|
| Название | «Парацетамол Эвалар 500 мг таблетки шипучие 12 шт» | str |
| Производитель | «Эвалар» | str |
| МНН | «Парацетамол» | str |
| Розничная цена | 208 ₽ | float |
| Наличие сколько в аптеках | **«В наличии в 277 аптеках»** | int |
| Rx/OTC (тумблер фильтра) | «Без рецепта» да/нет | bool |

**Уникальный сигнал у Озерки** — количество точек сети, в которых SKU есть в
наличии. Это фактически **прокси-глубина дистрибуции внутри одной сети** и
позволяет считать share-of-shelf по конкурентам, не имея объёма продаж.

### 1.4 Общее для всех трёх сетей

Отсутствует везде:
- Объём продаж (штуки, деньги)
- Остатки на складах
- ЖНВЛП флаг явно
- ПЦ флаг явно
- Штрих-код / SKU-ID

Присутствует везде:
- Розничная цена (₽)
- ТМ (в названии или отдельно)
- МНН (в названии или отдельно)
- Производитель (юрлицо)
- Форма / доза / упаковка

## 2. Приращение данных

Что БДЦ добавляет по сравнению с тем что уже есть в проекте:

| Ось | Было в PharmDash | Даёт БДЦ |
|---|---|---|
| Цена конкретной пачки | ❌ (только ПЦ-регистрационные) | ✅ реальная розничная |
| Ценовое позиционирование ТМ | ⚠️ (ASP из БДП = усреднение) | ✅ по каждому SKU |
| Дисперсия цен между сетями | ❌ | ✅ min/median/max/CV между 3 сетями |
| ТМ-уровень в модели | ⚠️ (`BdpRaw.tm` есть, но плохо показан) | ✅ ТМ становится first-class |
| Скидочная активность | ❌ | ✅ % SKU со скидкой, средняя глубина |
| Rx/OTC разрез | ❌ | ✅ по каждому SKU (частично) |
| Глубина дистрибуции внутри сети | ❌ | ✅ (Озерки: число точек с наличием) |
| Ассортимент сети | ❌ | ✅ полный список SKU по МНН в каждой сети |
| Скорость движения цен | ❌ | ✅ (при повторных выгрузках — динамика) |

**Главное приращение**: до БДЦ у нас была только средневзвешенная USD/UN цена
за год (ASP) на уровне производителя. Теперь появляется **SKU × сеть × дата**
матрица цен, из которой считаются позиционирование, конкурентность и здоровье
дистрибуции.

## 3. Онтология

Чтобы БДЦ не превратился в помойку, нужен явный уровень агрегации:

```
   МНН (Paracetamol)                                     ← БДП, ГРЛС ключ
    └── ТМ / бренд (Панадол, Реневал, Эффералган, ...)  ← новый first-class
         └── SKU / пачка (Панадол таб 500мг №12)         ← БДЦ, ПЦ ключ
              └── цена в аптеке (сеть × дата)            ← БДЦ строки
```

**Ключ SKU** = `(МНН_canonical, ТМ_canonical, форма_canonical, дозировка_normalized, pack_size_parsed)`.

Проблема: у трёх сетей SKU-названия **разные**. У eApteka есть «Все формы
выпуска» и производитель+страна вместе; у Ригла форма/доза/№ в названии
одной строкой; у Озерки — своя конвенция. Значит нужен **SKU-matcher**
поверх словаря `dictionary_entries` (там уже есть МНН, ТМ, форма — придётся
добить `strength_normalized`, `pack_size_parsed` и матч по «размытому»
именованию).

Свойство SKU-ключа: **стабильный между сетями и между БДЦ↔ПЦ↔БДП**. Это и
есть цель ETL.

## 4. Метрики SKU

### 4.1 Ценовой разброс между сетями

Простейшая, но сильная метрика.

```
sku_price_min      = min(price_eapteka, price_rigla, price_ozerki)
sku_price_median   = median(...)
sku_price_max      = max(...)
sku_price_range    = max - min
sku_price_cv       = std / mean          # коэф. вариации, безразмерный
```

**Что показывает:**
- `sku_price_cv < 0.05` — стабильная цена, конкуренция низкая или картель.
- `sku_price_cv 0.05..0.15` — здоровая розничная конкуренция.
- `sku_price_cv > 0.15` — сильный спред, есть арбитраж; в одной из сетей аномалия.

Полезно на карточке SKU и в drill-down производителя (у каких SKU что происходит).

### 4.2 Позиция SKU относительно ПЦ-потолка

Если для МНН+ТМ есть строка в `PcEntry.price_rub_no_vat` (регистрационная):

```
sku_vs_pc = sku_price_median / pc_ceiling_unit
```

Где `pc_ceiling_unit = price_rub_no_vat / pack_qty_parsed × pack_size_sku`.
Аккуратно: ПЦ приведена к «единице» (таблетка/мл), надо привести к пачке
конкретного SKU.

- `sku_vs_pc < 0.85` — headroom, рынок продаёт заметно ниже потолка (норма).
- `0.85..0.95` — упирается в потолок, любое повышение — риск.
- `>= 0.95` — «на потолке», нельзя поднять цену без нарушения ПЦ.
- `> 1.0` — сигнал ошибки в данных ИЛИ SKU не подпадает под ПЦ (проверить).

Это **первый раз** когда мы можем считать headroom не в среднем по производителю,
а **по конкретной пачке**.

### 4.3 Скидочная глубина

```
discount_pct = (old_price - new_price) / old_price        # если старая цена есть
promo_flag   = discount_pct > 0
```

По сети `discount_share_of_sku = count(SKU со скидкой) / count(SKU)`. Высокая
доля скидочных SKU у одной сети = агрессивное ценовое позиционирование.

### 4.4 Rx/OTC разрез

Если сеть отдаёт rx-флаг (eApteka «Самовывоз: рецептурный», Озерки «Без
рецепта») — можно вести rx/otc как атрибут SKU. Полезно, потому что:
- OTC SKU растут в аптечной рознице «естественно» (аптека их выгодно продвигает).
- Rx SKU движение цены жёстче контролируется, ПЦ и ЖНВЛП чаще применимы.

### 4.5 Наличие в сети (Озерки)

```
availability_ratio = pharmacies_with_sku / total_pharmacies_in_network
```

Из 3 сетей это дают только Озерки. Ценность огромная: **прокси-glubine
дистрибуции без объёма продаж**. По сути показывает «желание сети
держать этот SKU на полке» — а это уже коммерческий сигнал.

Пример: парацетамол Эвалар — 277 аптек, парацетамол Реневал — 231 аптека.
При равном МНН более широкое присутствие = либо больше спрос, либо лучше
байер-условия. То и другое — важные BD-сигналы.

## 5. Метрики МНН

### 5.1 Ценовой ландшафт МНН

Для конкретного МНН (например Тадалафил):

```
mnn_price_min_per_dose_mg    = min(sku_price / (pack_size × dose_mg))
mnn_price_max_per_dose_mg    = max(...)
mnn_price_median_per_dose_mg = median(...)
mnn_price_range_ratio        = max / min
```

**Ключевая нормализация**: цена **за миллиграмм действующего вещества**.
Тогда таблетка 5 мг за 500 ₽ и таблетка 20 мг за 1500 ₽ сравнимы. Именно
эту нормализацию мы обещали для ПЦ в `analytics_opportunities.md §5.6`,
и здесь она получает второй важный источник данных.

- `price_range_ratio < 3` — рынок ценово однородный.
- `3..10` — сегментация «бренд премиум + генерики эконом».
- `> 10` — есть явные ценовые выбросы (проверить).

### 5.2 «Ценовая пирамида» МНН

Для МНН считаем распределение SKU по ценовым тirам:

```
tier_premium   = SKU где price_per_mg > median × 2
tier_middle    = SKU где 0.5 × median <= price_per_mg <= 2 × median
tier_economy   = SKU где price_per_mg < median × 0.5
```

Матрица `(tier × BG/G × производитель)` показывает **кто в каком тire играет**.
Например, если оригинал в премиум, а генерики строго в эконом — это классика.
Если генерик забрался в премиум — это ценовой аномалит, требующий проверки
(может быть уникальная форма).

### 5.3 Ценовая близость к ПЦ (agg по МНН)

```
mnn_headroom_median = median(sku_vs_pc across all SKU with PC)
mnn_ceiling_share   = count(SKU где sku_vs_pc >= 0.95) / count(SKU с PC)
```

Если `mnn_ceiling_share > 0.5` — половина рынка упёрлась в потолок. Значит
для нового игрока цена уже задана, придётся либо нарушить, либо становиться
самым дешёвым.

### 5.4 Скидочная агрессивность МНН

```
mnn_discount_intensity = count(SKU со скидкой в любой сети) / total SKU
```

Растёт → рынок конкурентный или сети зачищают склад (проверить сезонность
и совпадения по датам).

### 5.5 Ценовые лидеры и «дно»

Топ-3 самых дорогих и топ-3 самых дешёвых SKU по МНН (обязательно с
нормализованной ценой за мг). Ставится в drill-down МНН на дашборде.

### 5.6 «Ассортиментная разница» между сетями

```
sku_in_eapteka_only  = SKU в eApteka \ (Ригла ∪ Озерки)
sku_common_all_three = SKU во всех трёх сетях
```

- Общие SKU — «фундамент» МНН, стабильно у всех сетей → эти самые ценнее
  сравнивать по цене.
- Уникальные SKU у одной сети — либо она эксклюзивно завозит, либо это
  «мёртвая позиция» у других.

## 6. Метрики рынка

Считать по всем МНН одновременно — получаем market-level картины.

### 6.1 Инфляция аптечного чека (при повторных выгрузках)

Требует истории выгрузок. Если каждую неделю/месяц парсим одни и те же SKU:

```
mom_price_change = (median_price_this_month - median_price_last_month) / prev
```

По МНН, по классу ATC, по всему рынку. Даёт **реальную розничную инфляцию**,
которую невозможно посчитать из БДП (там ASP годовой и включает микс).

### 6.2 Индекс здоровья цен

Композитный индикатор рынка (0..1):

```
health = (
  0.30 × (1 - ceiling_share)             # рынок далёк от ПЦ-потолка
  + 0.30 × (1 - price_cv_within_sku)     # однородность цен в рамках SKU
  + 0.20 × discount_intensity            # активность промо (=конкуренция)
  + 0.20 × availability_share            # наличие SKU в сетях
)
```

Показывает, насколько рынок «живой». Полезно как быстрый score на карточке рынка.

### 6.3 Индекс атаки на потолок

```
market_ceiling_pressure =
    Σ (SKU где sku_vs_pc > 0.9 умножить на его price_median)
    / Σ (SKU с PC и его price_median)
```

Взвешенная (по цене) доля SKU «у потолка». Растёт → пересмотр ПЦ близко.

### 6.4 Skewness розничной цены на классе ATC

```
skew_by_atc = skew({sku_price_per_mg for sku in atc_class})
```

Положительный сильный skew → большинство SKU дешёвые + небольшое количество
дорогих премиумов (генерический рынок). Отрицательный → нормально
распределены (более зрелый). Полезно на overview.

### 6.5 Ассортиментное покрытие рынка сетью

```
network_coverage = count(МНН в сети) / count(all МНН в БДП)
```

Показывает **как глубоко сеть влезает в наш рынок**. Если Ригла имеет
340 SKU × 100 МНН на выборке из 500 МНН рынка — покрытие 20%. Полезно для
выбора «репрезентативной» сети и для понимания смещения выборки.

## 7. Кросс-источники

### 7.1 БДЦ × БДП

| Метрика | Смысл |
|---|---|
| `retail_asp = median(sku_price)` vs `bdp_asp` | Разрыв розничной и средней цены |
| Совпадение производителей | Кто из БДП реально продаётся в рознице |
| Ассортиментная представленность ТМ | Топ ТМ по БДП vs топ ТМ в БДЦ |
| Розничная маржа vs BDP | Если знать закупку — можно оценить наценку сети |

**Практика:** matcher `(mnn_canonical, tm_canonical, producer_canonical)`
для соединения. У нас в БДП уже есть `producer_canonical`, надо добавить
`tm_canonical` (сейчас `BdpRaw.tm` без канонизации).

### 7.2 БДЦ × ПЦ

Уже описано в §4.2, §5.3. Главное — **реальный headroom по SKU**, а не по
производителю.

Дополнительно: **обнаружение серого импорта**. Если SKU есть в БДЦ, но нет в
ПЦ и нет в ГРЛС активных — либо этот SKU параллельного/серого импорта, либо
БАД, либо косметика. Диагностическая метрика.

### 7.3 БДЦ × ГРЛС

Полезно два кросса:

**A.** «Активная РУ есть, продаётся в рознице»
```
sku_matched_grls_share = count(SKU где производитель ∈ активные РУ) / all SKU
```
Ниже 90% — сигнал устаревания выгрузки ГРЛС или серого импорта.

**B.** «Активная РУ есть, продаж нет»
```
grls_holders_not_in_bdc = active_grls_holders \ bdc_producers
```
Кто зарегистрирован, но не выходит в розницу. Это **latent competitors на
розничном горизонте** (не путать с latent из §6.1 analytics_opportunities.md
где latent для BDP).

### 7.4 БДЦ × БДЦ (между сетями)

Уже описано в §4.1, §5.6. Итого:
- Совпадающие SKU → ценовой спред
- Расходящиеся SKU → ассортиментный gap
- Совместные скидки → сигнал промо-кампании производителя (bulk discount)

## 9. Decision Engine

Как БДЦ меняет уже существующий scoring (`services/scoring.py`).

### 9.1 Экономический score — новые входы

Сейчас: growth USD, growth UN, ASP-growth (усреднённые из БДП).

Добавить:
- **Реальная розничная цена и спред** (нормализовано за мг):
  - Высокая медиана + низкий CV = здоровый премиум-рынок ⇒ +2..+3.
  - Низкая медиана + высокий CV = «мёртвая земля» из-за ценового давления ⇒ -3.
- **Розничная маржа над ПЦ** (headroom): чем больше средний headroom, тем
  безопаснее заходить с новой ценой ⇒ +2 при headroom > 25%.
- **Аптечная инфляция** (при истории): растущая → BD может закладывать
  индексацию ⇒ +1..+2. Дефляция → сжатие маржи ⇒ -2.

### 9.2 Структурный score — новые входы

- **Ценовая пирамида**: доминирование эконом-тира (>70% SKU) — генерический
  рынок ⇒ структурно сложно; +2 если новичок в эконом. Если наш продукт в
  премиум-тир: важно чтобы SKU в премиум было мало (<10%) → +3.
- **Ассортиментное покрытие сетями**: SKU-фрагментация 100+ SKU у 3 сетей
  ⇒ рынок хаотичный, -2. 10-30 SKU — здоровая аккуратная выборка ⇒ +2.

### 9.3 Регуляторный score — новые входы

- **Атака на потолок**: `mnn_ceiling_share > 0.5` ⇒ -3 (регулятор скоро
  пересмотрит ПЦ, риск неопределённости).
- **Латентная РУ без BDC**: если у нас есть РУ, но SKU нет в рознице
  — сигнал что мы «на бумаге» → флаг для BD.
- **Rx/OTC-микс**: если рынок ≥80% Rx — оно требует медпредставительства,
  -1 к простоте входа; если >70% OTC — быстрее выход на полки, +2.

### 9.4 Новые red flags / drivers

Красные флаги:
- «Ценовой спред SKU > 2x между 3 сетями» — вероятная нестабильность.
- «>60% SKU у ПЦ-потолка» — риск переоценки ПЦ.
- «>40% SKU со скидкой в неделе» — сети чистят остатки, спрос падает.
- «Доминирует один ТМ (>60% SKU)» — сложно занять полку.

Драйверы:
- «Здоровый ценовой headroom по SKU (>25%)» — можно ставить цену свободно.
- «Розничная инфляция > 5% г/г» — рынок принимает индексацию.
- «Топ-3 SKU есть в наличии в 200+ аптек Озерки» — насыщенная дистрибуция.
- «Ценовая пирамида плоская (тонкий премиум)» — есть вход в премиум-нишу.

### 9.5 Новые next_checks

- «Проверить сколько наших потенциальных конкурентов у ПЦ-потолка»
- «Проверить SKU-совпадение с ГРЛС — нет ли серого импорта»
- «Проверить: наш SKU-размер (напр 500мг×20) — есть ли у 2-3 сетей вместе»
- «Сравнить розничную цену за мг с бенчмарком ATC-3»

## 10. Парсинг и подводные камни

### 10.1 Что сложно нормализовать

**A. Producer.** У eApteka «Обновление ПФК АО, Россия», у Ригла
«Фармстандарт-Лексредства…» (обрезанное), у Озерки просто «Эвалар». Надо
матчить через `dictionary_entries` с type='producer' — там уже накоплено
2766 записей.

**B. ТМ.** У eApteka явное поле «Бренд: Реневал». У Ригла и Озерки ТМ сидит
в названии, надо парсить: `<МНН> <ТМ> <форма> <доза> <упаковка>`. Есть
шанс, что ТМ отсутствует (тогда SKU называется просто «Парацетамол…»,
т.е. это дженерик без ТМ — тоже валидный кейс).

**C. Форма выпуска.** «таблетки шипучие», «таб.», «TAB», «таблетки покрытые
оболочкой» — уже есть словарь LF. Нужно добить синонимы, встречающиеся в
розничных названиях.

**D. Дозировка и упаковка** — важно расширить `_extract_dose` из
`routers/dashboard.py` (см. §9.1 analytics_opportunities.md — план вынести
в `services/normalize.py`) и добавить парсер `pack_size` (аналог
`pack_qty_parsed` из ПЦ).

**E. Rx/OTC.** У eApteka в тексте «Самовывоз: рецептурный», у Озерки —
тумблер фильтра. Флаг может быть косвенным и требует эвристики.

### 10.2 Что принципиально нельзя из ценовых выгрузок

- Объём продаж (не показывается).
- Долю рынка розницы конкретной сети (нет данных о фактической продаже).
- Эластичность спроса без история цен И объёма.
- Реальную цену продажи с учётом бонусной программы клиента (там только «Цена клуба»
  у некоторых сетей).

Значит: **BDC — источник ценовой позиции и ассортимента**, а не заменитель
БДП. БДП остаётся источником объёма и долей.

### 10.3 Что можно только при **регулярных** выгрузках (>=1/мес)

- Аптечная инфляция (mom, yoy)
- Скорость реакции цены на ПЦ-пересмотр
- Промо-цикличность
- Смерть/появление SKU (SKU churn)

**Рекомендация**: сразу проектировать `BdcSnapshot` таблицу с колонкой
`snapshot_date` — даже если сначала будет одна дата, потом это станет
временным рядом.

### 10.4 Смещение выборки

2-3 сети ≠ весь розничный рынок. Ригла и Озерки — федеральные; eApteka —
онлайн-платформа с широкой географией. Все три смещают выборку к:
- Крупным сетям (мелкие точки не представлены)
- Онлайн-каналу (влияние доставки на цену)
- Городам-миллионникам

Значит выводы про «розничную цену рынка» надо квалифицировать как «розничная
цена в этих сетях», а не «рынка целиком». В UI это надо честно называть —
не «розничная цена», а «розничная цена в BDC-панели».

## 12. TL;DR

### Главные находки

1. **БДЦ даёт то, чего у нас никогда не было** — **реальную розничную цену
   пачки**. ASP из БДП это среднее по производителю за год; BDC даёт
   цену конкретного SKU в конкретной сети сегодня.
2. **Уникальный сигнал Озерки** — количество точек сети с наличием SKU.
   Это единственный прокси-показатель глубины дистрибуции без объёма продаж.
3. **Цена за миллиграмм действующего вещества** становится главной
   нормализованной метрикой. Она снимает шум формы/пачки/дозы и позволяет
   сравнивать SKU как equal-basis.
4. **Reality-check для ПЦ**: `sku_vs_pc` показывает **реальный headroom
   до потолка** для каждой пачки. Ни БДП, ни ПЦ по отдельности этого не
   считают.
5. **Только 2-3 сети — это уже прокси розничного рынка**, но выборка
   смещена (крупные сети, онлайн, миллионники). В UI надо честно называть.

### Топ-5 быстрых win-ов (1-2 спринта)

1. **W23** «Медиана цены за мг» — новый KPI в Zone1 дашборда МНН.
2. **W22** Ценовой boxplot SKU (min/max/median между сетями) — Zone2.
3. **W24** Колонка «В N аптеках» у топ-конкурентов (Озерки).
4. **W26** SKU vs PC-headroom в drill-down производителя.
5. **W21** Ценовая пирамида (premium/mid/economy) на МНН.

### Что нельзя

- Настоящую эластичность спроса (без объёмов).
- Долю рынка в рознице (без чеков).
- Долгосрочные тренды до накопления истории (нужны 6+ мес выгрузок).

### Стратегическая рекомендация

Начинать не с парсеров, а **с онтологии SKU и SKU-matcher**. Именно матчинг
`(МНН, ТМ, форма, доза, pack) → sku_id` — критическая точка проекта.
Без надёжного матчинга вся ценовая аналитика превращается в мусор
(одна пачка учитывается как три разных SKU в трёх сетях).
