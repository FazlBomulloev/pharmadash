# Вход и фундамент под права доступа

Дата: 2026-10-15
Статус: дизайн согласован в чате, реализуется сразу

## Цель

Заменить браузерное окно Basic Auth собственной страницей входа и ввести
настоящую модель пользователей, чтобы разные уровни прав добавлялись позже
строкой в словаре, а не переписыванием.

Сейчас: один общий логин и пароль на уровне nginx (`auth_basic`), у бекенда
своей защиты нет вообще — он доверяет прокси. Достучавшись до `/api/` мимо
nginx, данные можно читать и менять без всякой аутентификации.

## Границы

- **Сейчас один аккаунт с полным доступом.** Многопользовательский режим с
  разными уровнями прав — следующая работа. Решение заказчика.
- Фундамент означает не «место, куда потом допишем», а рабочие точки проверки:
  роль в базе, словарь прав в коде и `Depends(require(...))` на изменяющих
  эндпоинтах с первого дня. У единственной роли право `*`, поэтому поведение
  не меняется, но когда появится вторая роль, запреты включатся сами.
- Регистрация, восстановление пароля и приглашения по почте не делаются.
  Аккаунты заводятся администратором (пока — через `.env`).

## Данные

`users`:

| Поле | Тип | Примечание |
|---|---|---|
| `id` | Integer | PK |
| `username` | String(100) | not null, уникален, хранится как введён |
| `password_hash` | String(128) | scrypt, hex |
| `password_salt` | String(64) | hex, свой на пользователя |
| `role` | String(32) | not null, default `admin` |
| `is_active` | Boolean | not null, default true |
| `created_at` | DateTime | not null |
| `last_login_at` | DateTime | nullable |

`sessions`:

| Поле | Тип | Примечание |
|---|---|---|
| `id` | Integer | PK |
| `user_id` | Integer | FK users.id, ondelete CASCADE, индекс |
| `token_hash` | String(64) | SHA-256 от токена, уникален, индекс |
| `created_at` | DateTime | not null |
| `expires_at` | DateTime | not null, индекс |

Новые таблицы создаются через `Base.metadata.create_all` в `init_db()`,
миграции в проекте не используются.

## Пароли

`hashlib.scrypt` из стандартной библиотеки: `n=2**14, r=8, p=1, dklen=32`,
соль 16 байт на пользователя. Измерено на целевой машине — 68 мс на проверку:
достаточно медленно против перебора, незаметно при входе.

Ни bcrypt, ни passlib, ни библиотеки JWT не добавляются. Новых зависимостей у
этой работы нет вообще.

Сравнение хешей — через `hmac.compare_digest`, чтобы время ответа не зависело
от того, насколько совпал хеш.

## Сессия

Токен — `secrets.token_urlsafe(32)`. В базе хранится только SHA-256 от него:
дамп базы не даёт войти, ровно так же, как с паролями.

Cookie `epi_session`: `HttpOnly`, `SameSite=Lax`, `Secure` (включается
переменной окружения, чтобы работала локальная разработка по http), `Path=/`,
срок 30 дней. Токен не кладётся в localStorage: оттуда его достанет любой XSS.

Выход удаляет строку сессии и гасит cookie. Просроченные сессии удаляются
лениво при обращении.

## Защита эндпоинтов

Зависимость `require_user` вешается на `include_router` сразу для всех шести
роутеров в `main.py`. Это единственное место подключения, поэтому забыть
роутер нельзя по построению.

Открыты без аутентификации только `POST /api/auth/login`,
`POST /api/auth/logout` и `GET /api/auth/session`.

## Права

`backend/services/permissions.py`:

```python
class Role(str, Enum):
    admin = "admin"

PERMISSIONS: dict[str, frozenset[str]] = {
    Role.admin.value: frozenset({"*"}),
}
```

`require(permission)` — фабрика зависимостей, пускает при праве `*` или точном
совпадении. Проверки ставятся сразу на изменяющие эндпоинты:

- `markets:write` — создание, удаление рынка, загрузка файла, маппинг;
- `directions:write` — заливка справочника направлений;
- `settings:write` — изменение настроек скоринга рынка;
- `pharmacies:write` — запуск сбора цен аптек.

Чтение не ограничивается ничем, кроме самого факта входа.

## Первый аккаунт

При старте, если таблица `users` пуста, создаётся пользователь из
`ADMIN_USERNAME` и `ADMIN_PASSWORD`. Если переменные не заданы — приложение
стартует, но пишет в лог предупреждение, что войти будет некем. Повторный
запуск существующего пользователя не трогает и пароль не перезаписывает.

## nginx

`auth_basic` и `auth_basic_user_file` удаляются из `frontend/nginx.conf`,
скрипт `frontend/docker/40-htpasswd.sh` и переменные `BASIC_AUTH_*` — тоже.
Иначе человек увидит два запроса пароля подряд.

**Порядок обязателен: сначала бекенд закрывается аутентификацией, только потом
снимается Basic Auth.** В обратном порядке приложение остаётся без защиты
вообще, пусть и ненадолго.

## Страница входа

Маршрут `/login`, вне `Layout` — без боковой панели.

Фон — глубокий navy бренда (`--color-ink`), по нему редкой сеткой идут
тепловые ячейки, те же, что в «Направлениях» и «Странах производства»,
приглушённые почти до фона. Это визуальный язык самого продукта, а не
отвлечённый узор: человек видит, куда входит.

На нём светлая карточка: логотип EPI, поля «Логин» и «Пароль» с переключателем
видимости, кнопка «Войти» цветом `ink`.

Что отличает сделанную страницу входа от собранной:

- **Автозаполнение Chrome.** `-webkit-autofill` красит поле своим жёлтым и
  ломает любой дизайн. Перебивается `box-shadow: inset 0 0 0 1000px` в цвет
  поверхности плюс `-webkit-text-fill-color`. Без этого страница развалится у
  всех, у кого сохранён пароль, — то есть почти у всех.
- **Caps Lock.** Подсказка под полем пароля, самая частая причина «не пускает».
- **Фокусное кольцо, каретка и выделение текста** — из палитры, а не браузерные
  по умолчанию.
- Enter отправляет форму; кнопка показывает состояние ожидания и блокируется,
  чтобы двойной клик не создал две сессии.

Ошибка — одной строкой под полями, говорит, что делать: «Неверный логин или
пароль» (не уточняя, что именно неверно — иначе логины можно перебирать).

После входа — возврат на страницу, куда человек шёл до редиректа, а не всегда
на главную.

## Поведение фронтенда при 401

Перехватчик axios: любой ответ 401, кроме самого запроса входа, отправляет на
`/login` с сохранением адреса возврата. Это закрывает истёкшую сессию и
перезапуск сервера.

`App.tsx` при старте спрашивает `GET /api/auth/session`. Пока ответа нет —
нейтральный экран ожидания, чтобы не мигать формой входа у уже вошедшего.
